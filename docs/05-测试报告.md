# 05-测试报告

## 测试环境

推荐演示环境：

| 项目 | 说明 |
|---|---|
| 前端入口 | `http://localhost:8088` |
| 后端健康检查 | `http://localhost:8088/api/health` |
| 后端就绪检查 | `http://localhost:8088/api/ready` |
| 后端直连 | `http://localhost:8080/api/health` |
| 数据库 | MySQL 8，端口 `3307` |
| 启动方式 | `docker compose up -d --build` |

如果本机没有 Docker，也可以使用本地 MySQL、Maven 和 npm 分别启动。

## 关键验证点

- 查看 `order_info` 是否新增订单主表记录。
- 查看 `order_item` 是否保存商品名称、价格和图片快照。
- 查看 `product.stock` 是否扣减，`product.sales` 是否增加。
- 查看 `cart_item` 中已结算商品是否删除。
- 模拟库存不足时，订单主表和明细不应产生脏数据。
- 查看 `/uploads/product/...` 是否能访问后台上传的商品图片。

## 接口测试文件

接口测试示例位于：

```text
mall-backend/api-test.http
```

该文件包含健康/就绪检查、登录限流、用户登录、管理员登录、主动退出、购物车、地址、带 `requestId` 下单、重复下单幂等、付款备注、管理员确认收款、发货、确认收货、取消订单和统计等接口示例。

自动化业务验收脚本：

```bash
node scripts/practical-flow-check.mjs
```

本阶段已覆盖：

- 健康检查。
- 数据库就绪检查。
- 登录失败限流。
- 修改密码后旧 Token 失效。
- 主动退出后旧 Token 失效。
- 401、403 权限响应。
- 低库存筛选。
- 商品图片上传和访问。
- 下单、付款备注、确认收款、发货、确认收货。
- 同 `requestId` 重复下单返回同一订单。
- 同一购物车项使用新 `requestId` 重复结算失败。
- 下单和取消订单会写入库存流水。
- 管理员确认线下收款会写入 `payment_order`。
- 待支付订单取消后库存和销量恢复。
- 禁用用户旧 Token 拦截。
- 管理员不能禁用自己。
- 用户订单概要。
