# 后续开发方案：可演示级交付路线

> 历史说明：本文档记录的是可演示级阶段的开发路线。当前项目已在后续迭代中升级订单流程，原文中的“模拟支付”不再代表当前实现；当前实现采用线下付款备注 + 管理员确认收款。

## 1. 目标定位

本项目下一阶段先不追求生产级商城，而是先做到“可演示级”。

可演示级的含义是：

- 可以在一台本地机器或局域网服务器上稳定启动。
- 可以通过浏览器完整演示普通用户购物流程和管理员管理流程。
- 可以展示数据库表在下单、支付、发货等关键动作后的变化。
- 可以用 README、接口测试文件和实验报告说明系统设计、数据库设计、测试依据和后续改进。
- 可以避免演示现场因为环境、端口、依赖、数据库初始化问题导致项目跑不起来。

可演示级不是生产级。当前阶段不要求真实支付、HTTPS 证书、云对象存储、复杂监控告警、CI/CD、分布式部署、高并发压测和完整售后系统。

## 2. 当前基线

项目已经完成一版课程大作业核心功能：

- 后端：Spring Boot 3、MyBatis-Plus、JWT、BCrypt、统一返回、统一异常。
- 前端：Vue3、Vite、Vue Router、Pinia、Axios、Element Plus。
- 数据库：MySQL 建表脚本、初始化数据、外键、唯一约束、检查约束、索引。
- 业务：注册登录、商品浏览、购物车、地址、订单、模拟支付、后台管理和统计。
- 文档：需求分析、系统设计、数据库设计、系统实现、测试报告、实验总结、答辩提纲。
- 验证：前端构建通过；后端源码使用 Java 17 + Maven 打包通过。

当前主要缺口：

- 没有统一的一键启动环境。
- 还没有在真实 MySQL 服务上完成完整联调记录。
- 前端仍以 Vite 开发服务器为主，没有通过 Nginx 托管静态资源。
- 演示脚本、截图证据、数据库观察步骤还不够完整。
- 核心失败用例和权限用例还需要补充验证。

## 4. 修正后的阶段路线图

### 阶段一：演示环境工程化

建议周期：0.5 到 1 天。

目标：让项目可以用统一命令启动，避免本地环境差异影响演示。

任务：

- 新增根目录 `.env.example`。
- 新增 `docker-compose.yml`。
- 新增 `mall-backend/Dockerfile`。
- 新增 `mall-frontend/Dockerfile`。
- 新增 `mall-frontend/nginx.conf`。
- 后端 `application.yml` 确认支持环境变量覆盖。
- MySQL 容器初始化时自动执行 `schema.sql` 和 `data.sql`。
- Nginx 托管前端静态资源，并代理 `/api` 到后端。
- README 增加 Docker Compose 启动说明。

建议服务结构：

```text
Browser
  ↓ http://localhost:8088
Nginx
  ├── /      -> Vue3 dist
  └── /api   -> mall-backend:8080
                  ↓
                MySQL 8
```

建议端口：

| 服务 | 容器端口 | 主机端口 |
|---|---:|---:|
| Nginx / 前端 | 80 | 8088 |
| Spring Boot | 8080 | 8080 |
| MySQL | 3306 | 3306 或 3307 |

验收标准：

- `docker compose up -d --build` 可以启动全部服务。
- 浏览器访问 `http://localhost:8088` 可以打开前端。
- 前端请求 `/api` 可以到达后端。
- 后端能连接容器内 MySQL。
- 默认账号可以登录。

数据库观察点：

## 10. 风险和应对

| 风险 | 影响 | 可演示级应对 |
|---|---|---|
| Docker 不可用 | 无法一键启动 | 保留手动启动方案：MySQL + Maven + npm |
| 端口冲突 | 服务启动失败 | README 写明端口修改方式 |
| MySQL 初始化失败 | 无法登录或无数据 | 提供重置数据库命令 |
| 前端无法调用后端 | 演示中断 | Nginx 统一代理 `/api`，减少跨域问题 |
| 初始化数据不够 | 演示单薄 | 增加多分类、多商品、多状态订单 |
| 订单演示失败 | 核心链路失效 | 演示前用 `api-test.http` 做检查 |
| Windows/WSL 权限问题 | 构建失败 | 推荐 Docker 构建或 WSL 本地盘验证 |
