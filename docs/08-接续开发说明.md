## 4. 重要环境和权限注意事项

### 4.1 Git 配置问题

当前项目位于 Windows/WSL 挂载盘。Git 写 `.git/config.lock` 时可能出现：

```text
chmod .../.git/config.lock failed: Operation not permitted
```

已采取的处理：

- 本地 `.git/config` 已设置 `core.filemode=false`。
- 已手动写入 `origin` 和当前分支 upstream 配置。

后续如果需要修改 Git 配置，优先使用正常 Git 命令；如果仍因挂载盘 chmod 失败，再直接编辑 `.git/config`，但必须先确认不会覆盖已有配置。

### 4.2 权限策略

后续开发不要为了绕过权限限制降低实现质量。

需要提权时，应直接申请提权，例如：

- 需要安装依赖。
- 需要访问网络下载镜像或依赖。
- 需要运行 Docker。
- 需要推送远程仓库。
- 需要修改 Git 配置。

### 4.3 文件安全

不要提交：

- `.env`
- `node_modules/`
- `dist/`
- `target/`
- 日志文件
- 数据库本地数据目录

当前 `.gitignore` 已覆盖常见构建产物和 `.env`。

### 5.4 修复真实联调问题

真实 Docker 联调后，常见可能问题：

- MySQL 初始化脚本因字符集或数据问题失败。
- 后端等待 MySQL 就绪时间不足。
- 前端 Nginx 代理路径不正确。
- 浏览器路由刷新 404。
- 外部图片 URL 加载慢。
- 初始化数据和演示脚本中的 ID 不一致。

修复后建议提交：

```text
fix: stabilize docker demo flow
```
