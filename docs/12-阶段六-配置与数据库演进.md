# 阶段六交付文档：配置与数据库演进

## 阶段目标

把配置拆分为开发和生产两套 profile，并明确数据库全量初始化与增量迁移的使用边界，避免后续部署时误删数据或使用演示配置。

## 完成内容

- 保留 `application.yml` 作为通用配置。
- 新增 `application-dev.yml`：
  - 本地开发默认数据库连接。
  - 保留 MyBatis SQL 日志，便于课程和调试展示。
- 新增 `application-prod.yml`：
  - `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` 必须显式配置。
  - `JWT_SECRET` 必须显式配置。
  - 关闭 MyBatis SQL stdout 日志。
  - 支持反向代理转发头。
- `.env.example` 补齐：
  - `SPRING_PROFILES_ACTIVE`
  - `DB_USERNAME`
  - `DB_PASSWORD`
  - `CORS_ALLOWED_ORIGINS`
  - 上传相关配置
- Docker Compose 后端服务显式传入 `SPRING_PROFILES_ACTIVE` 和数据库连接配置。
- 新增 `docs/database-migration.md`，说明：
  - 新环境执行 `schema.sql` + `data.sql`。
  - 旧环境按 `migration/` 脚本增量升级。
  - migration 前必须备份。

## 剩余边界

- 当前仍采用轻量 SQL migration 管理方式，尚未引入 Flyway 或 Liquibase。
- 服务器正式部署前，用户需要决定是否继续使用同机 MySQL，或改用云数据库并提供 `DB_URL`。
