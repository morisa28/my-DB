# 阶段十一：生产安全与运行稳定性加固

## 本阶段目标

基于 `docs/codex_next_development_prompt.md` 的 P0、P1 和 P7 要求，优先修复 `docs/17-整体隐患审查报告.md` 中影响小规模上线/内测的首批问题：

- MySQL 初始化 SQL 运行时单文件挂载在 Docker Desktop + WSL 场景下不稳定。
- `/api/health` 只能证明进程存活，不能证明数据库可用。
- 生产配置容易误用 demo 密钥、root 数据库账号和 `CORS=*`。
- 通用 500 错误会把内部异常消息返回给前端。

## 修改内容

### 1. MySQL 初始化镜像

新增 `mall-mysql/Dockerfile`，在构建阶段把 `schema.sql` 和 `data.sql` 复制到 `/docker-entrypoint-initdb.d/`。

`docker-compose.yml` 改为构建 `mall-platform-mysql` 镜像，不再把两个 SQL 文件作为运行时 bind mount 挂到 MySQL 容器中，降低 Windows / WSL 共享目录下重启 Docker 后挂载失效的风险。

### 2. 健康检查与就绪检查分离

后端保留：

```text
GET /api/health
```

该接口只表示应用进程可响应。

新增：

```text
GET /api/ready
```

该接口会执行 `SELECT 1` 检查数据库连接。数据库不可用时返回 HTTP 503 和统一错误文案。Docker 后端 healthcheck 改为访问 `/api/ready`。

### 3. 生产 Compose 与配置防呆

新增：

```text
docker-compose.prod.yml
.env.prod.example
```

生产 Compose 与本地演示 Compose 分离：

- 生产环境强制要求数据库 root 密码、应用数据库用户、应用数据库密码、JWT 密钥和 CORS 允许来源。
- 后端固定使用 `SPRING_PROFILES_ACTIVE=prod`。
- 后端使用 `MYSQL_USER` 连接数据库，不使用 root。
- MySQL 不映射宿主机端口，避免误暴露公网。

后端启动自检扩展为在 prod profile 下拒绝以下配置：

- JWT 密钥少于 32 字节、使用 demo 值或包含 `change-me`。
- CORS 为空或包含 `*`。
- 数据库用户名为 root。
- 数据库密码为空、过短、使用 demo 值或包含 `change-me`。

### 4. 500 错误信息收敛

全局异常处理不再把 `Exception#getMessage()` 返回给前端。未处理异常会写入后端日志，前端只收到：

```text
系统暂时不可用，请稍后重试
```

这样可以避免 SQL 错误、文件路径、约束名或框架内部信息泄露。

### 5. CI 基础检查

新增 `.github/workflows/ci.yml`，包含：

- 后端 Maven 测试。
- 前端 `npm ci` 与 `npm run build`。
- 本地演示 Compose 配置检查。
- 生产 Compose 配置检查。

## 兼容性影响

- 本地演示启动命令仍是 `docker compose up -d --build`。
- 首次构建 MySQL 服务时会构建自定义 `mall-platform-mysql` 镜像。
- 后端运行镜像会安装 `curl`，用于容器内 healthcheck。
- 生产环境不能继续使用 root 应用账号、demo 密钥或 `CORS=*`，否则后端拒绝启动。
- `/api/health` 返回结构不变；新增 `/api/ready`，不会破坏已有前端 API。

## 验证方式

建议执行：

```bash
git diff --check
cd mall-backend && mvn -B test
cd ../mall-frontend && npm ci && npm run build
cd .. && docker compose config --quiet
docker compose -f docker-compose.prod.yml --env-file .env.prod.example config --quiet
```

如需运行态验收：

```bash
docker compose up -d --build
curl http://localhost:8088/api/health
curl http://localhost:8088/api/ready
node scripts/practical-flow-check.mjs
```

## 未完成与风险

- 本阶段未实现 sessionVersion、登录失败限流、下单 requestId 幂等和库存流水。
- 本阶段未引入 Flyway/Liquibase；生产数据库仍需要严格避免执行包含 `DROP DATABASE` 的初始化脚本。
- `.env.prod.example` 仅是模板，服务器上必须替换所有 `change-me` 占位值。
- 如果服务器无法访问 Docker Hub 或 Debian/Ubuntu 软件源，首次构建镜像仍可能失败，需要配置镜像源或改为 CI 构建后推送镜像。

## 下一步建议

下一阶段优先做：

1. 登录安全：`session_version`、修改密码后旧 token 失效、登录失败限流。
2. 下单幂等：新增 `requestId`，同一用户重复提交只返回同一订单。
3. 数据库迁移：引入 Flyway 或至少拆分生产增量 migration。
4. 备份恢复：补数据库和上传目录备份脚本与演练文档。
