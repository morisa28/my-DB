# 阶段十一：第一批隐患修复

## 阶段目标

根据 `docs/17-整体隐患审查报告.md`，优先修复会影响部署可靠性和生产安全边界的隐患。本阶段聚焦 H1、H2、M1、M2、M4、M5，不处理订单并发幂等这类交易一致性大改。

## 完成内容

- 新增 `mall-mysql/Dockerfile`，把 `schema.sql` 和 `data.sql` 构建进 MySQL 初始化镜像，替代运行时单文件 bind mount。
- 更新 `docker-compose.yml`，MySQL 改为使用 `mall-platform-mysql` 镜像，移除初始化 SQL 文件挂载。
- 新增 `/api/ready` 就绪检查，实际执行 `SELECT 1` 验证数据库连接。
- 保留 `/api/health` 作为轻量存活检查。
- 后端容器新增 readiness healthcheck，检查 `/api/ready`。
- 新增 `docker-compose.prod.yml`，生产环境强制配置数据库用户、数据库密码、JWT 密钥和 CORS 来源。
- 新增 `.env.prod.example`，作为生产 `.env` 模板。
- 生产启动校验增强：
  - 禁止默认 JWT。
  - 禁止 `CORS_ALLOWED_ORIGINS=*`。
  - 禁止应用使用 root 数据库账号。
  - 禁止默认或过短数据库密码。
- 500 错误响应改为通用提示，完整异常仅写入后端日志。
- 分页参数增加 `page >= 1`、`1 <= size <= 100` 校验。
- 商品、分类、用户状态增加 `0/1` 范围校验。
- 订单状态查询增加 `0-4` 范围校验。
- `scripts/practical-flow-check.mjs` 增加 `/api/ready` 验收。
- README、部署前检查和运维手册同步更新。
