# 阶段十三：下单幂等与重复结算防护

## 本阶段目标

基于 `docs/codex_next_development_prompt.md` 的 P3 要求，补齐订单创建的客户端幂等能力，降低用户双击提交、网络重试或并发提交导致重复订单的风险。

本阶段聚焦：

- `OrderCreateDTO` 增加 `requestId`。
- 新增 `order_idempotency` 表。
- 同一用户同一 `requestId` 重复提交返回同一订单结果。
- 同一购物车项使用不同 `requestId` 重复结算时失败。
- 前端结算页自动生成并提交 `requestId`。

## 修改内容

### 1. 数据库结构

新增表：

```sql
CREATE TABLE order_idempotency (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    request_id VARCHAR(64) NOT NULL,
    order_id BIGINT,
    status TINYINT NOT NULL DEFAULT 0,
    create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_order_idempotency_user_request (user_id, request_id)
);
```

### 2. 后端订单创建流程

订单创建开始时先插入幂等记录：

```text
user_id + request_id
```

如果插入成功，说明当前请求获得创建资格。后续在同一事务中完成：

1. 校验地址归属。
2. 查询并校验购物车项。
3. 构建订单明细快照。
4. 删除待结算购物车项，声明这些购物车项已经被本事务结算。
5. 创建订单主表和明细。
6. 安全扣减库存。
7. 将幂等记录标记为成功并写入 `order_id`。

如果插入幂等记录时遇到唯一键冲突：

- 已成功且存在 `order_id`：返回原订单结果。
- 仍在处理中或状态异常：返回“订单正在处理中，请勿重复提交”。

如果后续创建失败，事务回滚，幂等记录也回滚，同一 `requestId` 可按业务错误修正后重试。

### 3. 前端结算页

结算页加载时生成一次 `requestId`：

```text
crypto.randomUUID()
```

提交订单时随 `addressId` 和 `cartItemIds` 一起发送。提交按钮已有 loading 状态，`requestId` 进一步覆盖网络重试或重复点击的服务端幂等。

### 4. 验收脚本

`scripts/practical-flow-check.mjs` 增加：

- 使用同一 `requestId` 重复调用 `POST /orders`，断言返回同一 `orderId`。
- 使用新 `requestId` 结算已被清理的同一购物车项，断言返回 400。

## 兼容性影响

- `POST /api/orders` 现在要求请求体包含 `requestId`。
- 前端已同步传入 `requestId`。
- `api-test.http` 已同步示例。
- 直接调用 API 的旧客户端需要更新请求体。
