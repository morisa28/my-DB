# 阶段十四：库存流水审计

## 本阶段目标

基于 `docs/codex_next_development_prompt.md` 的 P3.2 要求，新增库存流水能力，让库存变化不只体现在 `product.stock` 当前值，还能追溯变化来源、操作人、关联订单和前后库存。

本阶段覆盖：

- 下单扣库存：`ORDER_DECREASE`
- 取消待支付订单恢复库存：`ORDER_CANCEL_RESTORE`
- 管理员手动调整库存：`ADMIN_ADJUST`

## 修改内容

### 1. 数据库表

新增：

```sql
CREATE TABLE stock_movement (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    product_id BIGINT NOT NULL,
    order_id BIGINT,
    movement_type VARCHAR(32) NOT NULL,
    quantity INT NOT NULL,
    before_stock INT,
    after_stock INT,
    operator_id BIGINT,
    remark VARCHAR(255),
    create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

同步更新：

- `schema.sql`
- `migration/V20260520_3__stock_movement.sql`
- `docs/03-数据库设计.md`
- `docs/database-migration.md`

### 2. 下单扣库存流水

`OrderServiceImpl#createOrder` 在 `safeDecreaseStock` 成功后写入：

```text
movement_type = ORDER_DECREASE
quantity = 订单明细数量
before_stock = 下单前读取的库存
after_stock = 扣减后读取的库存
operator_id = 当前用户 ID
order_id = 当前订单 ID
```

库存扣减和流水写入在同一个事务中，任一步失败都会回滚。

### 3. 取消订单恢复库存流水

`cancelOrder` 恢复库存时写入：

```text
movement_type = ORDER_CANCEL_RESTORE
quantity = 订单明细数量
before_stock = 恢复前库存
after_stock = 恢复后库存
operator_id = 当前用户 ID
order_id = 被取消订单 ID
```

### 4. 管理员调库存流水

以下后台操作如库存值发生变化，会写入 `ADMIN_ADJUST`：

- 商品编辑表单修改库存。
- 商品管理页库存弹窗修改库存。

流水记录管理员 ID、调整数量、调整前后库存和备注。

## 兼容性影响

- 新环境直接执行 `schema.sql` 即可拥有库存流水表。
- 已有数据库需要执行 `V20260520_3__stock_movement.sql`。
- 现有 API 响应结构不变。
- 本阶段未新增前端库存流水页面，流水先用于数据库审计和后续后台查询扩展。

## 验证方式

建议执行：

```bash
git diff --check
cd mall-frontend && npm run build
cd ../mall-backend && mvn -B test
```

运行态可用以下方式人工核验：

```sql
SELECT * FROM stock_movement ORDER BY id DESC;
```

在执行下单、取消待支付订单、管理员修改库存后，应看到对应的 `ORDER_DECREASE`、`ORDER_CANCEL_RESTORE`、`ADMIN_ADJUST` 记录。

## 未完成与风险

- 暂未提供后台库存流水查询页面或接口。
- 下单扣减流水的 `before_stock` 来自扣减前业务读取值；在极端并发下，它主要用于审计参考，最终库存一致性仍以安全扣减 SQL 和 `after_stock` 为准。
- 尚未实现支付单、支付回调日志、退款售后模型。
