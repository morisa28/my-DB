# 阶段十七：备份恢复脚本

## 目标

本阶段补齐数据库和上传文件备份恢复能力，降低生产或内测环境误操作、漏备份、无法恢复的风险。

## 修改内容

- 新增数据库备份脚本 `scripts/backup-db.sh`。
- 新增上传文件备份脚本 `scripts/backup-uploads.sh`。
- 新增数据库恢复脚本 `scripts/restore-db.sh`。
- 新增脚本通用环境读取工具 `scripts/lib/env.sh`。
- 新增备份恢复文档 `docs/backup-and-restore.md`。
- 将 `backups/` 加入 `.gitignore`，避免备份产物误提交。

## 关键设计

数据库备份脚本优先使用 Docker Compose 中的 `mysql` 服务执行 `mysqldump`。如果服务未运行，则回退到本机 `mysqldump`，读取环境变量中的数据库连接信息。

上传文件备份脚本优先进入 `backend` 容器打包 `UPLOAD_DIR`。如果后端容器未运行，可以通过 `UPLOAD_SOURCE_DIR` 指定本机上传目录。

数据库恢复脚本默认恢复到 `${MYSQL_DATABASE}_restore`，用于演练和校验备份。脚本不会默认覆盖正式库；如确需覆盖，必须显式设置：

```bash
RESTORE_DATABASE=mall_db CONFIRM_RESTORE=I_UNDERSTAND bash scripts/restore-db.sh backups/db/<backup-file>.sql.gz
```

## 验证方式

语法检查：

```bash
bash -n scripts/lib/env.sh
bash -n scripts/backup-db.sh
bash -n scripts/backup-uploads.sh
bash -n scripts/restore-db.sh
```

配置检查：

```bash
docker compose config --quiet
docker compose -f docker-compose.prod.yml --env-file .env.prod.example config --quiet
```

完整演练需要 MySQL 或 Docker Compose 服务运行：

```bash
bash scripts/backup-db.sh
bash scripts/backup-uploads.sh
RESTORE_DATABASE=mall_db_restore bash scripts/restore-db.sh backups/db/<backup-file>.sql.gz
```

## 兼容性影响

- 不修改后端、前端业务接口。
- 不修改数据库表结构。
- 新增 `backups/` 忽略规则，只影响本地备份产物是否进入 Git。

## 未完成与风险

- 仍未引入 Flyway 或 Liquibase，当前继续沿用全量 `schema.sql` 和增量 migration SQL。
- 恢复脚本只负责数据库恢复，上传文件恢复目前保留为人工解压流程。
- 本阶段未在真实 MySQL 服务上执行完整恢复演练。
