# 阶段十八：CI 脚本检查加固

## 目标

本阶段在已有 GitHub Actions 基础上补充备份恢复脚本的语法检查，避免后续修改脚本时把语法错误带入主分支。

## 修改内容

- 更新 `.github/workflows/ci.yml`。
- 新增 `script-check` job。
- 在 CI 中执行：

```bash
bash -n scripts/lib/env.sh
bash -n scripts/backup-db.sh
bash -n scripts/backup-uploads.sh
bash -n scripts/restore-db.sh
```

## 当前 CI 覆盖范围

现有 CI 包含：

- `backend-test`：执行后端 `mvn -B test`。
- `frontend-build`：执行前端 `npm ci` 和 `npm run build`。
- `compose-config`：检查本地演示 Compose 和生产 Compose 配置。
- `script-check`：检查备份恢复脚本 Bash 语法。

## 兼容性影响

- 不修改业务代码。
- 不新增依赖。
- 不改变 Docker Compose 启动方式。
- 如果后续脚本语法错误，CI 会提前失败。

## 验证方式

本地验证：

```bash
bash -n scripts/lib/env.sh
bash -n scripts/backup-db.sh
bash -n scripts/backup-uploads.sh
bash -n scripts/restore-db.sh
docker compose config --quiet
docker compose -f docker-compose.prod.yml --env-file .env.prod.example config --quiet
```

前端构建验证：

```bash
cd mall-frontend
npm run build
```

后端测试验证：

```bash
cd mall-backend
mvn -B test
```

## 未完成与风险

- 本阶段只补 CI 配置，不代表 GitHub Actions 远端已经实际通过。
- 当前本地环境缺少 Maven 时，无法在本机执行后端测试。
- 还没有新增前端浏览器冒烟测试和后端业务单元测试。

## 下一步建议

- 增加前端冒烟测试或轻量页面可访问性检查。
- 增加后端核心业务测试，优先覆盖登录、下单、库存、取消订单和权限拦截。
- 后续如引入 Flyway，再把迁移校验纳入 CI。
