## 已完成能力

### 1. 生产部署安全

- 拆分本地演示 Compose 与生产 Compose。
- 生产 Compose 强制要求数据库密码、应用数据库用户、JWT 密钥和 CORS 来源。
- 生产环境后端固定使用 `prod` profile。
- 生产环境 MySQL 不映射宿主机端口。
- 后端在 `prod` profile 下执行启动安全自检，拦截 demo JWT、root 数据库账号、空密码和 `CORS=*`。
- `/api/health` 与 `/api/ready` 分离，容器健康检查使用数据库就绪检查。
- 全局 500 错误返回统一文案，避免向前端暴露 SQL、路径、约束名或堆栈信息。

### 2. 登录与会话安全

- 用户表增加 `session_version`、`last_login_time` 和 `last_password_update_time`。
- JWT 中加入会话版本。
- 修改密码、主动退出登录、管理员禁用用户后，旧 Token 会失效。
- 登录失败增加基础内存限流。
- 注册和修改密码增加复杂度要求。
- 管理员不能禁用自己。

### 3. 下单幂等与库存一致性

- 下单接口要求 `requestId`。
- 新增 `order_idempotency` 表，通过 `user_id + request_id` 唯一约束防止网络重试生成重复订单。
- 同一用户同一 `requestId` 重复提交时返回首次生成的订单。
- 事务内先声明购物车项清理，降低同一购物车项被不同请求重复结算的风险。
- 库存扣减继续使用条件更新，库存不足时回滚事务。

### 4. 库存流水审计

- 新增 `stock_movement` 表。
- 下单扣库存记录 `ORDER_DECREASE`。
- 取消待支付订单恢复库存记录 `ORDER_CANCEL_RESTORE`。
- 管理员调整商品库存记录 `ADMIN_ADJUST`。
- 文档中补充库存流水与订单、商品、操作人的关系说明。

### 5. 支付模型预留

- 新增 `payment_order` 支付单表。
- 新增 `payment_callback_log` 支付回调日志表。
- 管理员确认线下收款时生成 `OFFLINE` 成功支付单。
- 当前仍为线下付款演示流程，未接入真实第三方支付。
- 文档中明确后续真实支付回调必须校验签名、金额、订单状态并保证幂等。

### 6. 退款售后模型预留

- 新增 `refund_order` 退款售后单表。
- 新增 `refund_operation_log` 退款售后操作日志表。
- 预留申请中、审核通过、审核拒绝、退款中、退款成功、退款失败和已取消状态。
- 预留是否需要恢复库存和是否已恢复库存标记。
- 当前只完成模型预留，尚未实现退款接口、退款回调和库存恢复业务。

### 7. 备份恢复能力

- 新增数据库备份脚本 `scripts/backup-db.sh`。
- 新增上传目录备份脚本 `scripts/backup-uploads.sh`。
- 新增数据库恢复脚本 `scripts/restore-db.sh`。
- 新增通用环境读取脚本 `scripts/lib/env.sh`。
- 新增 `docs/backup-and-restore.md`，说明备份、恢复到临时库、禁止生产误操作等流程。
- `backups/` 已加入 `.gitignore`，避免备份产物误提交。

- 生产配置防呆。
- 登录会话版本失效机制。
- 下单幂等与库存安全扣减。
- 库存流水审计。
- 支付单和回调日志结构预留。
- 退款售后结构预留。
- 数据库和上传目录备份脚本。
- 基础 CI 检查。

仍不应视为完整生产级项目，尤其是支付、退款、测试覆盖、迁移体系和运维监控仍需继续补强。

## 剩余风险

- 尚未引入 Flyway 或 Liquibase，生产数据库迁移仍依赖人工按顺序执行 SQL。
- 后端业务自动化测试不足，关键流程主要依赖接口脚本和人工验证。
- 前端缺少浏览器级冒烟测试。
- 支付回调、退款回调、真实支付渠道尚未实现。
- 退款成功后的库存恢复事务尚未实现。
- 备份恢复脚本尚未在真实服务器环境做完整演练。
- CI 远端运行状态需要在 GitHub Actions 中确认。

## 下一阶段建议

优先级建议：

1. 引入 Flyway 管理数据库版本迁移，避免生产漏迁移或误执行全量 `schema.sql`。

6. 继续实现退款售后服务层和状态机，确保库存恢复与退款日志同事务落库。
